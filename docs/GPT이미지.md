# GPT·Gemini 이미지 모델 다루는 법

> CLAUDE.md 에서 옮겨 온 문서(2026-10). 인포그래픽·조감도·입체평면도를 만들 때 읽는다.

## GPT 이미지 모델 다루는 법 (OpenAI / Gemini)

쪽집게 노트 **인포그래픽**, 조경기사 실기의 **조감도·입체평면도**를 모두 이 모델로 만든다.
도구와 검증 요령은 아래에 공통으로 적고, 도면별 경위는 [docs/조경기사.md](조경기사.md).

**먼저 읽을 것 — 세 가지가 이 작업의 전부다.**

1. **화법**: 고칠 항목마다 먹히는 말이 다르다. 엉뚱한 화법을 쓰면 회차만 태운다
2. **덧그리기**: 화질을 깎는 것은 수정 항목 수가 아니라 **덧그린 횟수**다
3. **검증**: 만들고 끝내지 말고 **Claude 가 눈으로 + 화소로** 재고, 기준 미달이면 버린다

### 1. 화법 — 항목마다 먹히는 말이 다르다

401 입체평면도·조감도를 22장 그리며 갈린 것이다. **모델은 화면에서 비율을 재지 못한다.**

| 고칠 것 | 안 먹힌 말 | 먹힌 말 |
|---------|-----------|---------|
| 투영·시점 | "원근 없이" · "30° 기울여" | **재서 확인되는 조건** — "부지가 사다리꼴이 아니라 **평행사변형**" · "도로 띠 폭이 위아래로 **같다**" · "주택이 모두 **같은 크기**" · "깊이 비율 **0.71**" |
| 배치 | "부지 폭의 12% 지점" 같은 **백분율**(3연속 실패) | **"무엇을 지워라 / 늘려라"** — "관찰로 서쪽 열린 땅의 나무를 **모두 지우고** 빈 잔디로" |
| 개수 | "안내판은 3개여야 한다"(2연속 실패) | **자리를 짚고 세게 한다** — "데크 난간이 꺾여 끝나는 **모서리 바로 오른쪽**에 선 흰 판 액자를 지우고, **바로 아래 두 개와 똑같이 생긴** 걸상을 놓아라. 세어서 하나, 둘, 셋" |
| 빠진 식재 | — | **"가장자리를 따라 한 줄로 빈틈없이** 심어라, 끝에서 꺾어 아래 변도" |
| 수종 | 이름만 적기(참나무 셋은 그래도 다 같게 나온다) | **실루엣이 다른 것만** 이름을 적는다 — 은행나무(좁고 곧은 황록)·버드나무(늘어진 장막)·메타세쿼이아(뾰족한 원뿔) |
| 빈 잔디 | 말 안 하면 모델이 나무로 채운다 | **"열려 있어야 한다 · 정확히 N그루 · 세어라 하나, 둘, 셋…"** + 옆 화단을 "넓은 화단"이 아니라 "폭 3m 좁은 띠"로 |
| 지우면 안 되는 것 | (말 안 하면 사라진다) | **"관찰데크 5 + 조류관찰소 1 은 지우지 마라, 여섯이 모두 남아야 한다"** 를 따로 못박는다 |

- **자리는 붙박이 지형지물로 짚고, 개수는 끝까지 센다.** 세 번 다 이것으로 풀렸다 —
  모임광장 평의자 3(4회 실패 뒤), 진입광장 안내판 3(2회 실패 뒤), 메타세쿼이아 7주(**4회 실패 뒤**).
  좌표·백분율·"오른쪽 변을 따라"는 모두 소용없었다. 쓰는 법은 둘이다:
  ① **그림에 이미 있는 물건**을 기준점으로 — "나무가 심긴 네모 **수목보호대 두 개**가 박힌
     포장을 찾아, 그 **옆에서 시작해** 포장 가장자리를 따라 북으로"
  ② **"세어서 하나, 둘, 셋, 넷, 다섯, 여섯, 일곱"** 을 **끝까지 적는다**. "일곱 그루"만으로는 안 된다
  ③ 그래도 수가 틀리면 **틀린 경우를 짚어 준다** — "다섯 개다" 보다 **"셋이 아니다. 셋째가
     생기면 빼고 그 자리에 포장을 깔아라"** 가 들었다(수목보호대가 2 → 3 으로 늘던 것)
- **고치는 지시는 범위를 좁혀라.** "포장 가장자리의 키 큰 침엽수를 **모두** 지워라"가 통해서
  **맞게 서 있던 메타세쿼이아 열식까지 지웠다.** "무엇을 지워라"는 세면서 그만큼 난폭하다 —
  **"마운딩 옆 동선 가장자리의"** 처럼 자리를 한정해 쓴다
- **없어지면 안 되는 것은 매번 다시 적는다.** 한 회차에서 수목보호대가 5 → 3 으로 줄었다.
  "수목보호대는 **모두 다섯 개**다 — 남측 광장 둘, 북동 광장 둘, 모임광장 하나. 하나도 없애지
  마라" 를 넣으니 남았다
- **이미 맞게 그려진 것에 맞추게 한다** — "바로 아래 두 개와 똑같이 생긴". 새로 정의하는 것보다 쉽다
- **두 요구가 부딪히면 모델은 조용히 한쪽을 버린다 — 어느 쪽이 우선인지 적어라.** 안내판을
  "경계선과 나란히" 두면서 "판면이 비스듬히 보이게"까지 적었더니, 판면을 보이려고 **방향을
  되돌려** 버렸다(경계선과 나란하면 그 시점에서 판면은 안 보이는 것이 정상이다). 부딪히는
  요구를 빼고 **"방향이 최우선, 판면이 안 보여도 괜찮다"** 로 고쳐 잡았다. 그러고는 '안내판처럼
  보이게'를 판면이 아닌 **다른 단서**(다리 둘 · 판 아래 빈 틈 · 바닥의 그림자)로 옮겼다 —
  **원하는 것을 직접 말할 수 없을 때는 그것이 드러나는 부수 단서를 적는다**
- **실사를 주문하면 원근으로 되돌아간다.** 질감만 바꾸는 회차에도 위 표의 투영 조건문을
  **같은 프롬프트에 통째로 남기고**, 회차마다 화소로 재서 확인한다

### 2. 덧그리기 — 횟수가 화질을 깎는다, 항목 수가 아니다

같은 그림을 `--ref` 로 고쳐 그릴 때마다 물러진다. **항목을 몇 개 고치느냐는 상관없다.**

| 401 My 조감도 | 방식 | 선명도(라플라시안 분산) |
|---|------|------|
| 7회차 | 원본에서 **넷을 한 번에** | 1900 → 1781 (**−6%**) |
| 8·9회차 | 그 위에 **한 가지씩 더** | −23% · **−25%** |
| 10회차 | 원본에서 **다섯을 한 번에** | 1900 → 1835 (**−3%**) |

- **고칠 게 쌓이면 모아서 원본으로 돌아가 한 번에 간다.** 한 가지만 더 고치려다 25%를 잃었다
- **`--quality xhigh`($0.074)가 듣는 그림과 안 듣는 그림이 있다.** 입체평면도(회당 −6~10%)는
  `high` → `xhigh` 로 1015 까지 회복됐지만, 이미 6회 덧그려진 조감도는 `xhigh` 로도 −25% 를
  못 막았다. **원본에 남은 여유가 다르다** — 새 그림은 `high` 로 충분하고, 덧그린 그림을
  마무리할 때만 올린다
- **열화는 프롬프트로 못 막는다.** "어느 부분도 앞 회차보다 흐려지면 안 된다"를 박아도
  1125 → 942 에 그쳤다(회복 실패)
- 선화(모눈 도면 등)를 참고 그림으로 함께 주면 더 물러진다 — 뺐더니 −16% 가 −13% 로 줄었다

### 3. 검증 — 화소로 재고, 기준 미달이면 버린다

**회차마다 Claude 가 직접 연다.** 사람에게 "확인해 보세요"라고 넘기지 않는다.

| 재는 것 | 방법 | 기준 |
|---------|------|------|
| 평행투영 | 도로 띠 폭 3곳(높이별) · 모형 좌우변 기울기 · 주택 크기 | 폭이 같고 변이 거의 수직 |
| 화질 | 라플라시안 분산 — **전체 + 구역별** | 직전 배포본 대비 −12% 이내 |
| 개수 | 시설별로 세기 | 시설물 수량표와 일치 |
| 사용자가 짚은 자리 | `cv2.matchTemplate` 로 **배율을 훑어 조각의 위치를 찾는다** | 일치도 0.9 이상이면 확정 |

- **지표가 10% 낮아도 바뀌지 않은 영역을 2배로 확대해 1:1 로 견줄 것.** 입체평면도 −10% 는
  지붕 너와·난간 살·데크 널 이음매가 구분되지 않아 통과시켰고(잔디·수관의 고주파 잡티가
  줄었을 뿐), 조감도 −25% 는 잎이 뭉개진 것이 눈에 보여 기각했다. **수치만으로 판정하지 않는다**
  - **−18% 도 통과시킨 적이 있다**(My 조감도 10회차). 데크 널 개수가 같고 난간 두 가닥이
    여전히 틈을 두고 갈라지며 새순 갈래가 같은 자리에 같은 수만큼 있었다 — 넓은 잔디 면의
    질감 통계가 준 손실이지 물체의 해상이 준 것이 아니었다. **−25% 때는 같은 부위에서 잎이
    뭉개진 것이 한눈에 보였다.** 숫자가 아니라 이 차이를 보고 가른다
- **잴 수 있는 것과 없는 것을 가린다.** 개수·위치·평행투영은 화소가 정확하다. 그러나
  **각도와 밝기 대비는 화소로 재면 오히려 틀린다** — 안내판 각도를 PCA·그래디언트로 재니
  같은 판에서 **6° 와 29°** 가 나왔고, 밝은 판과 밝은 포장의 밝기 차이는 표본 상자를 어디에
  두느냐에 따라 **−36 과 −10** 이 다 나왔다(그늘·질감이 섞인다). 이런 항목은 4~6배로 확대해
  직전 회차와 나란히 놓고 **눈으로 판정하고, 무엇을 보고 그렇게 판단했는지 적는다**
- **기준을 먼저 적고 시작한다.** "①~⑤ 를 다 만족하면 채택, 하나라도 어긋나면 직전 것을 그대로
  둔다"를 정해 두면, 고쳐지긴 했는데 화질을 잃은 회차를 붙잡고 고민하지 않는다
- 회차 파일(`.txt` 프롬프트 + `.png`)을 **모두 남긴다** — 되돌리기도 한 번이고, 무엇이 나아졌는지
  견주려면 앞 회차가 있어야 한다

### 도구

두 갈래가 있고 **OpenAI 쪽이 기본**이다.

| 스크립트 | 모델 | 장당 | 한글 | 쓰임 |
|----------|------|------|------|------|
| `gen_note_image_gpt.py` | `gpt-image-2.5-sunburst` | 약 $0.04 | 4장에 오타 1건 | **최종 생성** |
| `gen_note_image.py` | `gemini-3-pro-image-preview` | 약 $0.13 | 한 장에 오타 5건 | 구성 잡기 |

```bash
python gen_note_image_gpt.py --prompt-file _p.txt --out _out.png
python gen_note_image_gpt.py --prompt-file _p.txt --out _out.png --ref 고칠그림.png
python gen_note_image_gpt.py --prompt-file _p.txt --out _out.png --round 2   # _out_r2.png
```

- 인자는 Gemini 판과 같다. 다른 점은 `--aspect` 대신 **`--size`**(픽셀 크기).
  기본 `1536x1024`, 세로 `1024x1536`, 정사각 `1024x1024`. 커스텀은 16의 배수·비율 1:3~3:1
- `--quality` 는 `low`~`max` 6단계, 기본 `high`
- `--ref` 를 주면 그 그림을 고쳐 그린다(`images.edits`)
- 키는 `.env` 의 `OPENAI_API_KEY`. `settings.OPENAI_IMAGE_MODEL` 로 모델 교체 가능
- **워크트리에서 돌릴 때 두 군데서 걸린다.** 이 스크립트는 `django.setup()` 을 하는데
  ① 시스템 파이썬에 `allauth` 가 없어 죽고 ② 워크트리에는 `.env` 가 없어
  "OPENAI_API_KEY 가 없습니다" 가 나온다. **venv 파이썬 + 본 저장소 `.env` 를 환경변수로**
  넘긴다(값은 출력하지 않는다):

```bash
set -a && . <(grep -E '^OPENAI_API_KEY=' "<본 저장소>/.env" | sed 's/\r$//') && set +a
"<본 저장소>/venv/Scripts/python.exe" gen_note_image_gpt.py …
```

### 인포그래픽만의 검증 — 글자와 사실

위 3절(화소로 재기)에 더해, **글자가 들어가는 그림**은 이것을 본다.

| 보는 것 | 불합격 예 |
|---------|-----------|
| 한글 글자 | 없는 글자, 자모가 깨진 글자, 프롬프트와 다른 낱말 |
| 내용 중복 | 같은 항목이 두 칸에 나옴 |
| 사실 오류 | 배에 유근이 둘, 잎차례가 설명과 다름 — 학술 그림은 특히 |
| 빠진 항목 | 프롬프트에 적은 항목이 그림에 없음 |
| 판독성 | 글자가 너무 작거나 배경에 묻힘 |

다시 만들 때는 `--round 2` 로 앞 회차를 남긴다 — 무엇이 나아졌는지 견줘야 한다.
잘 안 고쳐지는 항목은 프롬프트에 **정확한 문자열을 따옴표로 박아** 준다
("제목(정확히 이 글자): …", "글자가 깨지거나 없는 글자를 만들지 마세요").

### 겪어 보고 알게 된 것 (2026-09)

**두 번 실패한 글자는 낱말을 바꿔 우회한다.** `특징` 이 `톡징` 으로 두 번 연속 나왔고,
프롬프트에 "'특징'을 '톡징'으로 쓰지 마세요"를 박아도 안 고쳐졌다. `특징` → `성질` 로
바꾸니 한 번에 해결됐다. 같은 글자를 고집하는 것보다 뜻이 같은 다른 말이 확실하다.

**`--quality max` 는 쓸 일이 드물다.** 토큰이 4배로 뛰어 장당 $0.165 가 되는데
`high`($0.041)와 눈에 띄는 차이가 없었다. 덧그린 그림을 마무리할 때만 `xhigh` 를 쓴다(2절).

**사실 오류가 가장 놓치기 쉽다.** 한글만 보고 합격시키면 안 된다. 실제로 걸러낸 것:
휴면 유형 그림에서 "타발적 휴면"(발아하지 *못하는* 상태) 칸에 싹이 튼 새싹이 그려져
뜻이 정반대가 됐다. "싹·떡잎·뿌리를 그리지 마라"를 넣어 잡았다.

**구성은 Gemini, 최종 생성은 GPT** — 둘을 경쟁시키지 말고 역할을 나눈다.
Gemini 는 시키지 않은 좋은 구성(계층도·생활사 도해 등)을 제안하는 대신 한글 오타가
잦다(한 장에 5건: 겡게·꽃꽂·직용·꼭인발·비과). 그 구성을 받아 GPT 로 다시 그리면
정보량과 정확도를 모두 얻는다. 실제로 "잡초의 분류" 인포그래픽을 그렇게 만들었다.

**학술 그림은 도해가 사진보다 낫다.** 생장점 위치처럼 눈에 안 보이는 것을 보여야 할
때는 실사 대신 흙 단면 도해에 빨간 표시를 넣게 한다(화본과=밑동, 사초과=밑동+땅속
덩이줄기, 광엽=줄기 끝). 사진으로는 표현할 수 없는 내용이다.

**오타만 고칠 때는 `--mask` 로 자리를 찍어 준다.** `--ref` 만 주면 사진까지 전부 다시
그려진다(사용자가 "실사를 주는데 왜 바꾸느냐"고 지적한 원인). 고칠 글줄 자리만 투명한
PNG 를 `--mask` 로 함께 주면 그 자리를 맞춰 그리지만, **마스크 밖도 미세하게 흔들린다**
(평균 7/255). 그래서 결과에서 **마스크 영역만 잘라 원본에 얹는다** — 사진은 원본 픽셀
그대로 남는다. 자리는 눈대중이 아니라 글줄의 어두운 화소 띠를 재서 잡는다(눈대중으로는
윗줄을 물었다). "잡초의 발생실태"에서 8곳(밭뚝외풀·좀개구리밥·올챙이고랭이·여뀌바늘×3·
군락·괴경)을 이렇게 고쳤고, `밭`(받침 ㅌ)은 한 번 `발`로 나와 "ㅂ+ㅏ+받침 ㅌ, ㄹ이 아니다"를
박아 2회차에 잡았다. 크기는 16의 배수여야 하므로 1356 폭은 1360 으로 채운 뒤 되잘라 낸다.
