## 실기 필답형 (자연생태복원기사)

주관식 실기 필답형을 **출제 → 답안 작성 → AI 채점 → 점수 조정**으로 학습하는 기능.
필기(객관식)와 완전히 분리된 모델·뷰·템플릿을 쓴다.

### 시험 정보 (Q-net 출제기준 2025.01.01~2027.12.31)

| 항목 | 내용 |
|------|------|
| 과목명 | 생태복원 전문실무 |
| 검정방법 | 복합형 = **필답형(1시간 30분, 45점) + 작업형(3시간, 55점)** |
| 합격기준 | 합계 **60점 이상** (개별 과락 없음) |
| 출제기준 | 주요항목 8 / 세부항목 36 / 세세항목 142 |

> 일부 자료의 "필답 2시간"은 과거 기준이다. 출제기준 원문이 1시간 30분으로 명시.
> 합계 합격이라 **필답 30점을 확보하면 작업형은 30/55만 받아도 합격**한다.
> 결과 화면이 이 환산값(`session.practical_estimate`)을 보여준다.

- 조사 정리: `_eco_practical_exam_research.md` (시험 구조·합격률·수험생 후기)
- 출제기준 구조화: `_eco_exam_standard_2025.json` / `.md` (생성: `parse_eco_standard.py`)
- 원본 PDF: `data/comcbt/자연생태복원기사_출제기준_2025-2027.pdf`

#### 예상문제 395건은 걷어냈다 (2026-09)

교재 저자가 출제기준을 보고 만든 문항이라 **저작권 부담이 가장 큰 부분**인데,
학습 값어치를 재 보니 낮아서 제거했다. 최근 7회차 96문항을 두 재료로 각각 맞혀 보면:

| 재료 | 적중 |
|------|------|
| 과거 기출 | 11% |
| 예상문제 395건 | **4%** |

2024년 두 회차는 적중 0건이었다. **예상문제에만 있는 고유 주제도 0개**라
(기출 주제 563개 중 89개와 겹칠 뿐), 기출과 겹치는 110건을 빼면 나머지는
언젠가 나올 수도 있는 영역일 뿐이다. 문항 수가 기출의 절반이 넘어 여기 시간을
쓰면 기출 회독이 밀린다.

```bash
python deploy_essay_drop_pred.py   # 서버에서 실행 (응시 기록 있으면 중단)
```

- 백업: `_essay_predicted_removed.json` (395건 전문)
- **코드는 그대로 두었다** — `source='예상'` 경로가 살아 있어 자체 제작 문항을
  넣으면 바로 동작한다. 목록의 영역 카드는 데이터가 없으면 통째로 감춰진다
- 지울 때 응시 기록이 0건임을 확인했다. 기록이 있으면 사용자 이력이 사라지므로
  배포 스크립트가 스스로 중단한다

```bash
python merge_eco_essay.py --crop          # 판독 배치 병합 + 검증 + 이미지 크롭
python manage.py import_essay_questions   # JSON → DB
python manage.py normalize_essay_points   # 기출 회차 배점을 45점으로 정규화
python manage.py classify_essay_std       # 출제기준 주요항목 자동 분류
```

**배점**: 교재에 배점 표기가 없어 유형별로 부여한다(계산·서술·표그림 4 / 열거 3 / 빈칸·단답 2).
기출은 `normalize_essay_points`가 회차 합계를 45점에 맞춘다(0.5점 단위 가감).

### 모델 (gisa/models.py)

| 모델 | 설명 | 핵심 필드 |
|------|------|-----------|
| `GisaEssayQuestion` | 필답 문항 | source(예상/기출), section, year, round, number, qtype, text, **answer_items(JSON)**, answer_text, reference, points, rubric, std_major |
| `GisaEssaySession` | 응시 세션 | mode(online/paper), status, paper_code, total_points, score |
| `GisaEssayAttempt` | 문항별 답안 | answer_text, transcribed_text, ai_score, **final_score**, feedback(JSON) |
| `GisaEssayUpload` | 시험지 사진 | page_no, image, transcribed |

- **답을 `answer_items`(리스트)로 저장하는 것이 핵심.** 교재 풀이가 이미 `①②③` 포인트
  단위라, 그대로 채점 기준표가 된다. 배점을 항목 수로 나눠 부분점수를 준다.
- **① 항목 수는 문제가 묻는 것의 수와 같아야 한다.** "정의와 특징을 서술하시오"면
  ① 정의 ② 특징. 특징을 ②③④로 쪼개면 답의 뼈대가 문제와 어긋난다. 한 항목 안의
  세부 열거는 ㉠㉡㉢ 으로 적는다. "N가지"를 묻는 열거형은 N개 항목이 맞다.
  (2026-09 정비: 무선추적법·비오톱 기능·극상 특징·파편화 저감방안 등 9문항)
- **한 가지만 묻는 서술형("X란 무엇인지 설명하시오")은 ①② 없이 문장으로 쓴다.**
  `answer_items` 는 문장 하나(줄바꿈으로 문장 구분), 채점 포인트는 `rubric` 에
  따로 둔다 — 화면은 문장, 채점은 포인트별 부분점수. (2026-09 정비 29문항, 백업
  `_essay_prose_backup.json`). 단순 라벨→"은/는" 기계 변환은 "결과는 …" 같은
  어색한 문장을 만들므로 직접 다시 써야 한다
- `answer_text`는 표·계산식처럼 항목으로 쪼갤 수 없는 답.
- `reference`(법조문·지침·배경 설명)는 **채점에 쓰지 않고** 학습 자료로만 노출.
  화면 라벨은 **「해설」** (2026-09 변경, 이전 "참고자료 (법조문·지침)").
- `final_score`가 있으면 그것이, 없으면 `ai_score`가 점수다(`attempt.score` 프로퍼티).

### 저작권 — 답·그림·문제문을 모두 다시 씀

원본이 예문사 교재라 **세 갈래를 전부** 손봤다. 하나라도 남기면 의미가 없다.

| 대상 | 처리 |
|------|------|
| 답 (`answer_items`·`answer_text`) | 전량 재서술 (Claude 직접, 외부 API 미사용) |
| 그림 65장 | 자작 SVG로 교체. **구도까지 바꿔야 한다** — 좌표만 옮기면 "거의 같다"는 지적을 받는다 |
| 문제문 (`text`) | 987건 재서술 (2026-09). 당시 1,121건 대상이었고 이후 예상문제 395건은 삭제 |
| 예상문제 395건 | 통째로 삭제 — 저작권 부담 대비 적중률 4% (위 참조) |

> 기출 문항 **번호는 바꾸지 않는다.** 회차별 번호는 교재의 편집이 아니라 국가시험
> 사실이고, 과거 응시 기록(`GisaEssayAttempt`가 `question__number`로 정렬)과
> 다른 수험 자료 대조가 걸려 있다.

**사실은 저작물이 아니다** — 법조문, 수치 기준, 분류 체계, 계산식은 그대로 둔다.
보호되는 것은 **표현과 도해의 구성**이다.

#### 문제문 재서술 강도 — "조사 정도만"

사용자 지시가 명확했다: *"너무 용어나 많이 고치지 말고, 조사 정도를 바꿔서 문장만"*.
수험자가 느끼는 문제는 완전히 같아야 한다.

| 바꾸는 것 | 그대로 두는 것 |
|-----------|----------------|
| 어미 `~하고자 한다`→`~하려고 한다`, `~일 경우`→`~라면` | 전문 용어 전부 (매토종자·비오톱·SLOSS…) |
| 조사 `중`→`가운데`, `~에 따른`→`~에 따라` | 수치·법령명(낫표 포함)·답 개수 지시 |
| 문장 끊기/잇기, 조건절 위치 | `[box]` 지문 내용, 마크다운 표 |
| 괄호 단서를 `(단, …)`로 분리 | 묻는 내용과 요구 사항 |

> 용어를 풀어 쓰면 안 된다. "매토종자"→"묻혀 있던 씨앗"은 **문제를 새로 쓴 것**이다.
> `SLOSS 논쟁에 대하여 설명하시오` 정도로 이미 최소인 문장은 `~이란 무엇인지`까지만.
> 억지로 못 바꾸겠으면 원문 유지가 정답이다 (실제 134건이 그랬다).

```bash
python dump_essay_text_rewrite.py            # 40건씩 29배치
# → 병렬 에이전트 6개가 batch_NN_done.json 저장 (배치마다 즉시 저장 필수)
python load_essay_textrw.py                  # 검증만
python load_essay_textrw.py --apply          # DB 반영 (_essay_text_backup.json 자동 백업)
python deploy_essay_text.py export / load    # 서버 배포
```

`load_essay_textrw.py`가 원문과 자동 대조해 **수치 누락·답 개수 지시 변경·법령명 소실·
`[box]`/표 구조 파손**을 잡아낸다. 하나라도 걸리면 그 건만 보류한다. 실제 987건 중 위반 0건.

> **자격증 pk가 로컬 6 / 서버 3으로 다르므로** 배포 스크립트는 pk가 아니라
> `(source, section, year, round, number)`로 문항을 찾는다.

#### 원문 오식은 이때 함께 잡는다

재서술하며 답과 대조하면 오식이 드러난다. 실제로 정정한 것:

| 오식 | 정정 | 근거 |
|------|------|------|
| `CFC` | `CEC` | 답이 Cation Exchange Capacity |
| `NH⁺` | `NH₄⁺` | 답 표기 |
| `옆면적 지수` | `엽면적 지수` | 답이 LAI 정의 |
| `IUCN LED LIST` | `IUCN 적색목록(Red List)` | — |
| `2,000본/m³` | `2,000본/m²` | 파종량이 g/m²라 면적 단위 |
| `100,0000m²` (2023-1 #6) | `100,000m²` | 모범답안이 100,000 기준으로 계산 |
| `등고선 10m와 110m` (2024-1 경사도) | `등고선 100m와 110m` | 모범답안이 표고차 10m(20%)로 계산. 사용자 확인 후 정정 |

**단, `[box]` 지문 안의 오식은 손대지 않는다** — 복원문제집이라 원문 보존이 우선이다.
확신이 없으면 그대로 두고 `notes`에 기록한다.

### 채점 엔진 (gisa/essay_grading.py)

**답을 쓴 문항은 모두 LLM이 채점한다.** 반환 형식은 어느 경로든 같다.

| 유형 | 엔진 | 방식 |
|------|------|------|
| 빈 답안 | `rule` | 호출 없이 0점. 채점이 아니라 처리다 |
| 계산 | `rule` → `llm-calc` | 최종 답 수치가 전부 맞으면 규칙으로 만점. 어긋나면 계산 전용 LLM |
| **그 밖의 전부** | `llm` | 채점 기준표의 포인트마다 "답안이 이 내용을 담았는가" 판정 |

**프롬프트는 종목을 알려 준다**(`_exam_header`). "국가기술자격 실기 필답형"이라고만
하면 모델이 어느 분야인지 모른 채 용어를 판정한다. 문항의 자격증과 `EXAM_INFO` 의
`practical_subject` 를 합쳐 `[시험] 식물보호기사 실기 필답형 · 과목 「식물보호실무」 ·
필답 100점 만점` 을 프롬프트 맨 위에 붙인다 — '엽면적지수'와 'LAI', '무황산근'과
'황산근이 없는 비료'가 같은 말인지는 그 분야를 아는 채점위원이라야 가른다.
계산형 프롬프트도 같은 머리말을 쓴다.

**배점을 주고 점수를 매기게 한다**(2026-09). 프롬프트의 채점 기준표에 항목별 배점이
적혀 있고(`1. (2.5점) ① 최적엽면적`), 모델이 항목마다 `matched` 와 **`score`(그 항목에
주는 점수)** 를 돌려준다. 부분 점수도 여기서 나온다 — "배점 2.5점짜리를 반만 맞혔으면
1.25". 예전에는 "부분적으로만 맞으면 matched=false" 라 항목 단위로 전부 아니면
전무였고, 한 가지만 묻는 서술형처럼 **기준표가 한 항목뿐인 문항은 0점 아니면 만점**만
나왔다. 단답·빈칸은 배점 전부 또는 0만 주도록 못박았다 — 맞거나 틀리거나 둘뿐이다.
계산형도 같아서 `answer_score`(배점의 70% 이내)와 `process_score`(30% 이내)를 받는다.

> **코드가 하는 일은 자르기와 더하기뿐이다.** 채점 판단은 전부 모델이 하되,
> 항목 점수가 배점을 넘거나 음수면 잘라 내고(9.9 → 2.5, -3.0 → 0), 합계는
> 파이썬이 낸다 — 덧셈은 모델이 틀릴 이유가 없는 대신 틀리면 점수가 어긋난다.
> `matched=true` 인데 `score` 를 0 으로 보내면 판정을 따라 배점 전부를 준다.
>
> 화면은 부분 인정을 **△ '부분 인정 1.25/2.5점'** 으로 그린다
> (`.pt.half`·`.rs-pt.half`). ✕ 로 두면 점수가 붙은 까닭을 알 수 없다.

한때 단답·빈칸을 문자열 비교로 채점했으나 **걷어냈다**(2026-09-01 `082da86`).
모범답안이 "야생절멸(EW)"인데 "야생절멸"만 쓴 정답을 0점 처리하는 사고가 났다.
동의어·표기 변형·괄호 부연·띄어쓰기 같은 예외는 규칙으로 끝이 없고, **틀리게 일관된
채점은 사용자가 채점 자체를 불신하게 만든다.** 아끼는 비용은 세션당 1원 미만이라
정확도와 바꿀 값어치가 없다. 관용 규칙은 대신 프롬프트에 적어 두었다(괄호 부연은
선택 사항 / 띄어쓰기·맞춤법 무시 / 빈칸 번호기호 무시).

> **계산형의 규칙 경로(수치만 맞으면 만점)도 걷어냈다**(2026-09-15). 조경
> 학원예상 1회 7번에서 `42.67 m2/hr`(정답 m³/hr)에 만점을 줬다 — 숫자만 보고
> **단위를 못 봤고**, 허용 오차 2% 때문에 `3.2 x 0.8` 을 쓴 답안이 중간값 2.56 과
> 맞은 것으로 잡혔다. 이제 답을 쓴 계산형은 모두 `llm-calc` 다. 배점의 70%를 답
> 정확성, 30%를 과정에 배분한다(답이 맞으면 과정을 생략해도 70%는 준다).
>
> **단위 규칙은 `CALC_SYSTEM` 에 있다** — 실기 답안 작성 유의사항 그대로다.
> 단위가 틀리면(m²/hr ↔ m³/hr) 수치가 맞아도 답 점수 0(과정 점수는 줄 수 있음),
> 단위를 빠뜨렸을 때는 문제가 단위를 지정했으면(`작업량(m³/hr)을 구하시오`) 정답,
> 지정하지 않았으면 오답. `m3`·`m2` 같은 위첨자 없는 표기는 같은 단위로 본다.
> 실측: m2/hr 0.9/3 · m3/hr 3/3 · 단위 생략 3/3.

만점 보정: 균등 배분(4점 ÷ 3항목 = 1.33)에서 생기는 반올림 오차 때문에 전부 맞아도
3.99점이 나온다. 모든 포인트가 matched면 만점으로 올린다.

#### '3가지를 쓰시오'인데 모범답안이 5가지일 때 — 셋만 맞혀도 만점 (2026-09)

"토양 공기를 지배하는 요인을 **3가지** 쓰시오"의 모범답안은 토성·토양구조·경운·
토양수분·유기물 **다섯**이다. 이 다섯은 '다 써야 할 것'이 아니라 **인정되는 답의
목록**이므로, 셋을 맞혔으면 만점이다. 그런데 기준표를 5항목 × 1점으로 쪼개 놓고
더하기만 하니 3점이 나왔다(식물보호기사 2025-2회 4번). 보기 목록형 문항은
로컬 기준 **43건**이다.

**보기 묶음은 모델이 짚고, 코드는 관문만 지킨다.** 규칙으로 가르려 하면
'정의를 쓰고 3가지를 설명하시오' 같은 합성 문항까지 만점이 된다 — 그 판단은
문제를 읽어야 나온다. 그래서 채점 응답에 두 칸을 더 받는다:

| 필드 | 내용 |
|------|------|
| `pick_count` | 문제가 요구한 개수. 보기 목록이 아니면 0 |
| `pick_indices` | 서로 바꿔 써도 되는 기준표 항목 번호. **정의·개념처럼 반드시 써야 하는 항목은 넣지 않는다** |

코드(`_pick_group`)는 모델 말을 그대로 믿지 않고 세 가지를 본다 —
① `pick_indices` 가 `pick_count` 보다 많아야 한다(같으면 그냥 다 써야 하는 문항이다),
② **그 개수가 문제문에 실제로 적혀 있어야 한다**(`asked_count`), ③ 문제문의 '가지'
세는 자리가 **하나뿐**이어야 하고 '각각'·'씩'이 없어야 한다.

> ③이 합성 문항을 걸러낸다. 'A를 2가지와 B를 3가지'는 자리가 둘이라 다섯을 다
> 써야 하는 문항이고, '논과 밭에 각각 1가지씩'은 대상마다 따로 요구한 것이다.
> 정의+N가지 꼴은 ①이 막는다 — 보기 묶음이 딱 N개라 `len(idx) > need` 가 안 된다.
> `asked_count` 의 한글 수사 앞에는 `(?<![가-힣])` 를 둔다. 없으면 '다양**한** 가지'의
> '한'을 1로 센다.

점수는 **보기 묶음의 배점 전부를 요구한 개수로 나눠** 준다(`_sum_points`). 다섯
항목에 1점씩 붙어 있어도 셋만 요구했으면 하나가 1.67점이다 — 셋 맞히면 5점,
둘이면 3.33점. 부분 점수도 비율로 반영된다. **모범답안이 10가지든 20가지든
분모는 요구 개수**라 셋만 맞히면 만점이다.

**요구한 개수보다 많이 쓰면 먼저 쓴 것부터 그 개수까지만 센다.** 실기 채점은
더 쓴다고 봐주지 않는다 — 셋을 요구했는데 넷을 적었다면 앞의 셋으로 판단하지,
맞은 것만 골라 주지 않는다. 그래서 채점 응답에 `answer_order`(수험자가 쓴
차례대로 그 항목의 기준표 번호, 기준표에 없는 답은 0)를 함께 받아 앞의 N개만
점수에 넣는다(`_written_order`). 넘겨 쓴 항목에는 `over` 를 달아 화면이 회색으로
"3가지를 넘겨 쓴 항목입니다"라고 밝힌다 — 맞은 항목이 ✓ 인데 점수가 없으면
왜인지 알 수 없다.

> **차례는 기준표가 통째로 보기 묶음일 때만 본다.** '정의를 쓰고 3가지'처럼
> 반드시 써야 하는 항목이 섞이면 쓴 차례 가운데 어느 것이 보기인지 가릴 수
> 없다(정의가 첫 칸을 먹어 보기 하나가 잘려 나간다). 점수를 준 항목이 차례에
> 빠져 있어도 모델이 대충 적은 것이므로 버리고 '잘 맞힌 것부터' 방식으로 돌아간다.

요구한 개수를 채웠으면 못 쓴 보기에 `alt` 를 달아 화면이 **빨간 ✗ 가 아니라 회색
점**으로 그린다(`.rs-pt.alt`). ✗ 로 두면 만점인데도 감점당한 것처럼 읽힌다.
같은 까닭으로 **만점이면 `missing`('↳ 빠짐: …')을 지운다.**

실측(2025-2회 4번, 요구 3 · 모범답안 5):

| 답안 | 점수 |
|------|------|
| 셋, 모두 정답 | 5.0 / 5.0 |
| 넷, 앞의 셋이 정답 (넷째는 `over`) | 5.0 / 5.0 |
| 넷, 첫째가 오답 | 3.33 |
| 다섯, 첫 둘이 오답 | 1.67 |
| 둘만 씀 | 3.33 |

한해 대책(6항목 중 3)도 5.0/5.0. 합성 문항은 그대로다 — 환경영향평가(정의+5항목)에서
정의를 빼면 3.35/4.0, 여울과 소(차이 2가지+영향)에서 영향을 빼면 1.76/3.5.

### 손글씨 사진 판독 (gisa/essay_ocr.py)

**판독과 채점을 반드시 분리한다.** 한 번에 시키면 오독인지 오답인지 구분할 수 없다.
판독 → 사용자 확인·수정 → 채점 순서다.

정확도를 올리는 두 장치:
1. **그 시험지의 문항 번호·문제문**을 함께 보낸다 → 문항 경계 판정에 결정적
2. **모범답안에서 뽑은 용어 목록**(회차당 ~130개)을 힌트로 준다 → 한글 받침 오독 감소
   `_collect_terms()`가 조사(`을/를/이/가/에서…`)를 떼고 명사만 남긴다.
   "매트이식", "톨훼스큐", "대체서식지" 같은 고유 용어가 잡히는 게 핵심.

프롬프트에 한글 자모 혼동쌍(ㄴ/ㄹ, ㅁ/ㅇ, ㅂ/ㅍ, ㅐ/ㅔ …)을 명시하고,
"목록에 없는 낱말을 목록의 낱말로 억지로 바꾸지 말 것"이라는 안전장치를 둔다.

> 답안은 한글이 주 언어이고 영문 약어(LID, HGM, GPP, IUCN)와 화학식이 섞인다.

### 사용 모델 — **전부 `config/settings.py` 에 모여 있다**

코드에 모델 이름을 박지 않는다. 그 모델이 종료되거나 갈아탈 때 찾아다니지
않으려는 것이고, preview 를 박아 두면 종료되는 날 그 기능이 통째로 죽는다.

```python
GEMINI_ESSAY_GRADE_MODEL = 'gemini-3.8-flash'        # 실기 채점
GEMINI_ESSAY_OCR_MODEL   = 'gemini-3.1-pro-preview'  # 손글씨 판독 (정확도 우선)
GEMINI_EXPLAIN_MODEL     = 'gemini-3.8-flash'        # 객관식 선지별 해설
GEMINI_QNA_MODEL         = 'gemini-3.8-flash'        # 질의응답
GEMINI_MODEL             = 'gemini-3.8-flash'        # 그 밖(기출 파싱·잡초 조회)
ESSAY_DAILY_GRADE_LIMIT  = 20   # 사용자당 하루 채점 횟수(세션 수)
ESSAY_DAILY_OCR_LIMIT    = 40   # 사용자당 하루 판독 장수
```

모두 같은 이름의 환경변수로 덮어쓸 수 있고, 해설 생성 명령은 `--model` 도 받는다.
**손글씨 판독만 preview 다** — 한글 손글씨 정확도 차이가 커서 감수한 선택이다.
비용 때문에 flash 로 옮길 이유는 없다. 2026-09 에 같은 시험지 1쪽(입력 2,951토큰:
사진 1,100 + 프롬프트 1,851)을 재 보니 **pro 약 11원**($0.0080, 생각 토큰 없음),
**3.8-flash 약 7원**($0.0048, 출력 161 + 생각 531 이 출력 단가로 청구)이었고, flash 는
2027-01-01 부터 단가가 두 배라 **pro 보다 비싸진다**(약 13원). 한 번 flash 로 바꿨다가
이 측정을 보고 되돌렸다.

> **preview 모델은 쓰지 않는다** — 예고 없이 종료된다. 2026-09 에 판독을 뺀 전 용도를
> `gemini-3.8-flash` 로 맞췄다. 판독만 정확도 때문에 preview 를 감수한다. 모두 환경변수로 교체 가능.

#### 시험 개요 (`gisa/essay_examinfo.py`)

**배점·시간은 자격증마다 다르다.** 자연생태복원기사는 필답 45 + 작업 55, 조경(산업)기사는
필답 40 + 작업 60이다. 화면 여러 곳에 45·55가 박혀 있었으므로 새 자격증을 붙일 때
`EXAM_INFO` 에 넣고 템플릿이 그 값을 쓰게 한다(실기 목록 머리말이 그렇게 바뀌었다).

- 출처는 **Q-net 종목별 상세정보의 '취득방법'**(`crf005.do?id=crf00503&jmCd=`, 조경기사
  1370 · 조경산업기사 2320)과 **출제기준(2025~2027)** 둘이다. 취득방법 본문은 페이지의
  `#contents_text_0` textarea 안에 iframe 용 HTML 로 들어 있어, 눈으로는 안 보여도
  거기서 읽으면 된다
- **시험시간 합계 표기가 자료마다 다르다.** 조경기사는 출제기준 '5시간 정도' vs 취득방법
  '4시간 30분 정도', 산업기사는 '3시간 30분' vs '4시간'. 구성(필답+작업)은 같으므로
  화면에는 **어림 합계가 아니라 필답·작업 각각의 시간**을 보여 주고, 차이는 각주로 남긴다
- `EXAM_INFO` 에 없는 자격증은 개요 화면이 목록으로 되돌리고 링크도 내지 않는다
- **학습전략(`essay_strategy`)은 정리 자료(`GisaEssayNote`)가 있는 자격증에만 연다.**
  본문이 '빈출 58주제'·'계산 공식 18' 같은 자연생태복원 자료를 전제로 쓰여 있어, 조경에서
  열면 45점·15문항 같은 남의 수치를 읽게 된다(뷰도 redirect, 링크도 `{% if notes %}`)

#### 합격 전략(`essay_pass`) — 글은 문서 한 벌만 둔다 (2026-09)

회원에게 "무엇부터 공부할지"를 알려 주는 글이다. 실기 페이지 히어로와 쪽집게 노트
머리글에 **혼자 노란 버튼(`★ 합격 전략`)**으로 붙어 있다 — 다른 링크는 흰색·반투명인데
처음 온 사람이 가장 먼저 보아야 할 글이라 색을 달리했다.

- **본문은 `docs/실기합격전략.md` 를 읽어 렌더한다.** 템플릿에 글을 적어 두면 두 벌이
  되어, 회차가 늘어 재출제율을 고칠 때 한쪽만 고쳐 어긋난다. 문서 머리말(작성 경위·
  갱신 방법)은 회원에게 보일 것이 아니므로 **첫 `---` 앞을 잘라 낸다**
- **문서가 있는 자격증에만 연다**(`PASS_DOCS`). 본문에 그 종목의 수치가 박혀 있다 —
  재출제율·분야 비중·"잡초방제학은 건너뛰어도 된다". 학습전략을 `freq58` 노트로 거르는
  것과 같은 까닭이며, 없는 자격증은 뷰가 목록으로 돌려보내고 링크도 내지 않는다
- 식물보호 두 급수와 **자연생태복원기사**(`docs/자연생태복원_실기합격전략.md`)가 있다.
  다른 종목에 붙이려면 **그 종목 수치로 글을 새로 써서** `docs/` 에 두고 `PASS_DOCS`
  에 등록한다 — 남의 수치를 그대로 보이면 안 된다
- **결론이 종목마다 반대일 수 있다.** 식물보호는 기출이 18장뿐이라 재출제율이 높아
  "빈출을 좁게 파라"가 맞지만, 자연생태복원은 51회차에 서로 다른 주제가 469개라
  **좁히면 무너진다** — 기출 주제를 전부 훑으면 최근 8회차 평균 29.3/45점인데,
  2회 이상 반복된 주제만 보면 14.4점, 3회 이상만 보면 6.6점이다. 글을 옮겨 쓰지
  말고 그 종목 데이터로 다시 세야 하는 까닭이다
  - 세는 법: 회차마다 "그 문항의 `topic_key` 가 **앞선 회차에** 있었나"를 보고
    `points` 로 가중해 만점으로 환산한다. 회차를 더하면 문서의 수치부터 고칠 것
- 수치의 근거와 갱신 방법은 문서 머리말에 적어 두었다(기출 22개 회차 438문항 기준)

**필기와 실기는 목록에서부터 완전히 분리한다.** 자격증 목록(`/gisa/`)은 **'필기'와
'실기' 두 묶음**으로 나뉘고(`written`·`practical`, 묶음 안은 자격증 이름순), 한
자격증이 양쪽에 한 장씩 들어간다. 실기 카드는 `essay_list`로 직행한다.

**카드 색이 그 다음 화면의 색이다.** 필기 카드는 남색(`#f3f5ff` 바탕·`#3949ab` 띠),
실기 카드는 초록(`#e9f4ec` 바탕·`#2d6a4f` 띠) — 필기 상세·기출고사가 남색이고 실기

> 아홉 장이 줄줄이 늘어서 어느 것이 무엇인지 한눈에 들어오지 않았다. 묶음을
> 나누니 배지가 필요 없어져 뺐고(머리말이 이미 말한다), "필답형 주관식 · 인쇄해서

    - 결과 화면은 뷰가 `pen_items`(attempt pk → 채점 결과)를 내려준다. 점수는
      사용자가 조정한 값(`attempt.score`)이고, 조정하면 답안지 점수도 다시 그린다.
      답안에 표(`| … |`)가 있으면 첨삭 답안지 대신 서버가 표로 그린 `qr-mine` 을 보인다
    - 점수 표시(`.mk-score`)에 흰 배경을 깔지 말 것 — 첫 줄 끝 첨삭 글씨를 덮는다
    - 첨삭 글(`.mk-note`)은 **inline + line-height:0** 이어야 한다. inline-block 이면
      좁은 화면에서 줄 끝 첨삭이 답안지 오른쪽 테두리 밖으로 삐져나간다
- `essay_save` 는 임시저장이 아니라 **진행률 채점 1단계**라 status 를 `grading` 으로
  바꾼다. 임시저장은 `essay_draft`(`/essay/<sid>/draft/`) — 입력 2초 뒤 서버에
  attempts 로 묶어 저장하고, 화면을 떠날 때도 한 번 보낸다. 이어하기(`?resume=`)가
  이 초안을 textarea 에 채운다. localStorage 초안은 새로 고침 대비용으로 병행

- 실기 카드: 왼쪽 다크그린 띠 + `실기` 배지, "기출 N회차 · 문항 N개" 표기
- 실기 페이지 hero 우측에 `필기로 ›` 전환 링크
- 회차 수는 `(year, round)` 조합을 세야 한다. `Count('round', distinct=True)`는
  회차 번호(1·2·3)만 세어 10회차가 3으로 나온다. `values_list().distinct()`를 쓸 때는
  **`order_by()`로 `Meta.ordering`을 지워야** 한다(정렬 필드가 SELECT에 끼어들어
  중복 제거가 무력화된다)
- 기출은 90분 타이머 (예상문제 경로는 무제한 10문항씩이나 현재 데이터 없음)
- 답안은 `localStorage`에 자동 임시저장 (15문항 쓰다 날아가면 치명적)
- 결과 화면에서 **사용자가 점수를 직접 조정**할 수 있다(`final_score`). AI 오채점 보정용이며,
  `ai_score`와 따로 저장하므로 나중에 채점 품질을 점검할 수 있다.

### `[box]` 가 표로 끝나면 상자가 닫히지 않던 버그 (2026-09 수정)

`_render_box` 는 `'<div …>' + inner + '</div>'` 로 **줄바꿈 없이** 이어 붙인다.
상자 안이 마크다운 표로 끝나면 마지막 줄이 `| … |</div>` 가 되고, 뒤이어 도는
`_tables_anywhere` 가 그 줄을 표의 한 행으로 먹어 **닫는 태그가 사라진다.**

증상이 엉뚱한 데서 나타나 원인을 찾기 어렵다 — 상자가 안 닫히니 **뒤따르는
문항이 통째로 그 상자 안으로 말려들어가고**, 화면에서는 그 문항의 정답 보기
버튼·편집 폼·답 영역이 사라진 것처럼 보인다. 2026-1회 7번(조건 상자가 표로
끝난다)에서 겪었고, 12문항 가운데 편집 폼이 11개만 렌더되는 것으로 드러났다.

`_tables_anywhere` 가 표 블록의 마지막 줄에서 **뒤에 붙은 닫는 태그를 떼어
두었다가 표 뒤에 도로 붙인다.** 새 문항을 넣은 뒤에는 아래로 한 번 훑어
확인하면 된다.

```python
o = Counter(re.findall(r'<(\w+)(?=[\s>])', html))
c = Counter(re.findall(r'</(\w+)>', html))   # 열림 != 닫힘 이면 깨진 것
```

### 관리자 인라인 편집 (실기 학습 화면)

판독본의 오식이나 원도와 다른 그림은 **학습 화면에서야 드러난다**. 그때마다
고침 스크립트를 새로 쓰는 것은 느리고 무엇을 고쳤는지도 흩어지므로, 스태프는
그 자리에서 바로 고친다 — 눈 버튼 옆 연필(`btn-edit`) → 문제문·답 항목·답
서술·해설 네 칸.

- `essay_question_update`(`/gisa/<id>/essay/edit/<qid>/`, POST JSON, 스태프 전용).
  화면의 `{% if request.user.is_staff %}` 와 **서버의 is_staff 를 둘 다** 본다
- **답 항목은 칸을 하나씩 준다.** 한 칸에 줄 단위로 넣을 수 없다 — 계산형 항목은
  그 안에 줄바꿈(`계산)
…`)이 이미 들어 있어 줄로 가르면 항목이 쪼개진다.
  빈 칸은 저장할 때 버린다
- **고친 자리만 다시 그려 돌려준다**(`text_html`·`ans_html`). 새로 고치면 열어
  둔 답이 도로 접히고 읽던 자리를 잃는다. 답 영역은 화면과 **같은 조각**
  (`gisa/_essay_answer.html`)을 렌더해 두 벌이 어긋나지 않게 한다
- **답 항목을 고치면 `rubric` 을 비운다.** 채점 기준표는 답 항목에서 파생되므로
  (`build_rubric`) 예전 것이 남으면 화면과 채점이 어긋난다
- 답 서술이 400자를 넘으면 `<details>` 로 접어 둔다 — 자작 SVG 가 통째로 들어
  있어(뿌리분 그림 3,700자) 펼쳐 두면 다른 칸이 안 보인다

### 시험지 인쇄 → 사진 제출 흐름

실기는 실제로 손글씨라 이 경로가 실전에 더 가깝다.

```
① 시험지 인쇄 (문항 + 답안 박스 + 시험지 코드)
② 볼펜으로 풀기
③ 페이지별 촬영 → 업로드
④ 판독 결과를 화면 textarea에 자동 채움
⑤ 사용자가 확인·수정
⑥ 제출 → 온라인 모드와 같은 채점 파이프라인
```

- **시험지 코드는 "연도-회차"(예: `2026-2`)로 고정**이다. 세션마다 다른 코드를
  주던 때는 먼저 인쇄한 시험지가 다음 세션에서 "다른 시험지"로 거부됐다. 시험지
  보안이 필요한 서비스가 아니므로 회차만 가린다. 판독기는 사진의 코드가
  연도-회차 꼴인데 다를 때만 거부하고, 안 읽히거나 다른 꼴이면 인쇄된 발문
  대조로 넘긴다(`_code_mismatch`)
- 코드는 모든 쪽 **바닥 가운데**에 찍힌다. `position:fixed` 글자 + `<tfoot>` 빈 칸
  조합이다 — fixed 만 쓰면 본문과 겹치고, `<tfoot>` 에 글자를 넣으면 마지막
  쪽에서 바닥까지 내려가지 않는다
- 답안 박스에 **굵은 테두리**를 두는 이유: 모델이 문항 경계를 찾는 데 결정적
- **인쇄 시험지**의 박스 높이는 유형별로 다르다 (단답·빈칸 3줄 / 열거·표그림 6줄 /
  서술·계산 8줄, 줄 간격 32px). 종이는 나중에 덧붙일 수 없어 넉넉히 뽑아야 한다
- **화면 풀이(`essay_take`)는 유형과 상관없이 3줄로 연다**(2026-09). 괘선·줄 간격은
  시험지와 같고 줄 수만 다르다 — 화면은 쓰는 대로 `autoGrow` 가 늘려 주므로(6줄을
  쓰면 196px) 미리 벌려 둘 까닭이 없다. 서술형을 8줄로 열어 두었을 때는 빈 칸만
  화면을 채워 한 화면에 한 문항밖에 안 들어왔다. 두 화면이 CSS 를 공유하지 않으므로
  (`ln1`·`ln2`·`ln3` 은 `essay_take` 안에만 있었다) 한쪽만 고치면 된다
- `@media print`로 A4 최적화, `page-break-inside: avoid`로 문항 잘림 방지

#### 사진 곧게 펴기 (gisa/essay_rectify.py, 2026-09)

사진을 고르면 **판독 전에** 서버가 A4(10px/mm, 2100×2970)로 편 사진을 만들어
보여 주고(`essay_flatten`), 판독은 그 편 사진으로 한다(`GisaEssayUpload.flat_image`,
원본 `image` 는 그대로 둔다). 줄이 곧아야 판독이 낫고, 나중에 사진 위에 첨삭을
겹쳐 그릴 좌표도 이 편 사진 기준이다.

| 순서 | 방법 | `flat_method` |
|------|------|---------------|
| 1 | 인쇄 시험지 네 모서리의 **ArUco 마커**(DICT_4X4_50 의 0 왼위·1 오른위·2 오른아래·3 왼아래). 두 개만 보여도 편다 | `marker` |
| 2 | 마커가 없으면 **종이 가장자리**(밝고 채도 낮은 영역의 볼록껍질 네 극점). 옛 시험지·문서 스캔 앱 사진 | `edge` |
| 3 | 둘 다 실패하면 원본(EXIF 회전만) | `none` |

1·2 뒤에 **휜 종이를 한 번 더 맞춘다**(`_refine`). 답안 박스의 굵은 테두리와
**점선 괘선**이 곧아야 하므로, 휜 만큼을 가우스 가중 변위장으로 만들어 `remap` 한다.

- **마커 위치는 인쇄 CSS 와 짝이다.** `@page` 여백 10/10/12mm, 마커 9mm, `position:fixed`
  네 모서리. 본문이 덮지 않게 `<thead>` 12mm·`<tfoot>` 11mm 빈 칸을 둔다. 크롬
  PDF 로 뽑아 재 보니 8쪽 모두 계산 위치와 0.1mm 안에서 맞았다. 바꾸면
  `MARGIN_*_MM`·`MARKER_MM` 을 같이 바꿀 것
- 마커 무늬는 `MARKER_BITS` 에 박아 두어 **시험지 화면은 OpenCV 없이** 그린다
- 선 뽑기 기준 길이는 **3mm**. 6mm 로 두니 휜 구간에서 테두리가 끊겨 표본이 비었고,
  선 높이 한도 4mm 는 휜 테두리를 통째로 뺐다(지금 12mm)
- 실측: 실제 사진 8장(마커 없는 옛 시험지) 모두 `edge`, 테두리 휨 0.5~0.7mm → 0.1~0.2mm.
  인쇄 이미지를 휨 4mm·원근으로 비튼 합성 사진은 선 오차 중앙값 1.4mm → 0mm
  (마커 2개를 가려도 0.5mm). 장당 0.6~0.9초
- **사진 여러 장을 한꺼번에 고르면 요청이 겹쳐 같은 쪽 번호를 잡아 500 이 났다.**
  서버는 `_new_upload` 가 번호를 올려 다시 넣고, 화면은 한 장씩 차례로 보낸다
  (서버 작업자가 2개라 한꺼번에 보내면 다른 사람 화면도 멈춘다)
- 판독 전 업로드는 하루 한도에 들지 않는다(`transcribed=False`). 하루 지난 것은
  다음 업로드 때 치운다. 판독 전 사진은 ×로 빼면 파일째 지운다(`essay_upload_remove`)
- 서버 패키지 `opencv-python-headless==5.0.0.93`. **4.12 는 numpy 를 2.2 로 내리므로
  쓰지 않는다**(서버 numpy 2.4 를 kiwipiepy 가 쓴다)
- **가장자리로 편 것은 시험지인지 확인한다.** 곧게 선 가로 표본이 150개, 세로 30개에
  못 미치면 원본으로 판독한다(`info['rejected']`). 흰 책상·이불 위에서 종이와 배경이
  섞이면 엉뚱한 사각형으로 펴기 때문이다. 실제 시험지는 가로 583~1,417 · 세로 89~162,
  글만 있는 흰 종이는 가로 44였다. 마커로 편 것은 검사하지 않는다

#### 내 시험지 첨삭 (gisa/essay_overlay.py, 2026-09)

결과 화면에서 **입력한 답안 첨삭 ↔ 내 시험지 첨삭**을 오간다(시험지 사진으로 낸
세션만). 내 시험지 첨삭은 **시험지를 자르지 않고 쪽 그대로** 보이며, 첨삭 글을 그 쪽의
**빈자리에** 손글씨로 적는다. 쪽은 문항 차례로 정렬해 그 쪽 문항 카드들 바로 앞에
끼우고, 카드에서는 문제문·입력칸 답안지를 감춘다(항목 판정·모범답안·해설은 카드에 남는다).

> 거쳐 온 길: ① 쪽 전체 + 카드 감춤 → 총평·판정이 사라져 "부실하다" ② 문항 박스만
> 잘라 카드에 넣음 → "시험지를 자르면 현실성이 떨어진다" ③ 지금: 쪽 그대로, 빈자리 활용

**빈자리 찾기**
- 서버가 1mm 칸마다 잉크가 있는지(`ink_grid`, 210×297 packbits base64)를 판독 때 계산해
  `flat_info['grid']` 에 둔다(이전 쪽은 첨삭을 처음 열 때 계산해 저장). **점선 괘선은
  잉크로 치지 않는다** — 괘선 위에 글을 쓰는 것은 자연스럽다
- 화면이 손글씨 글꼴로 글 폭을 재어(`document.fonts.load` 뒤 canvas `measureText`)
  가리키는 곳에서 가장 가까운 빈 사각형(누적합)에 적고, 적은 자리를 채운다
- 거리 = 가로 + 2.2×세로 — 같은 줄 옆이 가장 자연스럽다. 총평은 가로 가중치 4(새 줄 선호)
- **문항마다 범위를 막는다**: 앞 문항 박스 아래 ~ **다음 문항 발문 첫 줄 전**(행 잉크
  12칸↑). 넓게 두었더니 총평이 다음 박스 안이나 발문 줄에 앉아 그 문항 것처럼 읽혔다.
  범위는 글 덩이의 **아랫변**에 건다(윗변에만 걸었더니 두 줄째가 발문 줄로 내려앉았다)
- 칸 좌표는 정수로 반올림할 것 — 76.3 같은 소수가 들어가 모든 자리가 '안 빔'이 됐다

**무엇을 어디에**
- 구절 표시(줄 긋기·✗·물결·✓) → 첨삭 글이 **같은 줄 바로 옆**에 들어가면 번호 없이 글만,
  아니면 번호 동그라미 + 가까운 빈자리에 "① 글". 표시·동그라미 자리는 먼저 채워 둔다
  (비워 두면 글이 제 동그라미 위에 앉았다)
- ✓ 에 "정답"·"맞음" 만 붙은 첨삭은 적지 않는다 — 쪽마다 수십 개 늘어 틀린 곳이 묻혔다
- 빠짐 → 마지막으로 쓴 줄 아래. **그 줄 오른쪽은 막는다**(총평이 이어 붙어 한 문장처럼 읽혔다)
- 문항 점수 → 인쇄 배점 '(5.0점)' 옆(발문 줄 ~ 박스 첫 줄), 만점은 동그라미
- 총평 → 박스 아래 틈. 못 적으면 **카드의 총평이 그대로 보이므로 목록에 되풀이하지 않는다**
- 전체 점수 → 첫 쪽 머리 왼쪽 위 빈자리(사용자 요청). 60%↑ 두 줄 밑줄
- 끝내 자리가 없는 첨삭·점수만 쪽 아래 목록(`.sv-more`)
- 실측(세션 146 재현 · 8쪽 20문항): 목록으로 넘어간 것 0, 총평 17/20 시험지에, 계산 0.3초
- 좌표는 편 사진 픽셀(2100×2970)

**자리는 LLM 에게 묻지 않고 이미지에서 찾는다.** 한 번 LLM 좌표로 해 보니 가로는
맞는데 세로가 반 줄씩 흔들렸다. 편 사진에서는 인쇄물이 곧아 분석이 확실하다.

1. 판독할 때(`transcribe_uploads`) 쪽마다 `page_layout` 을 계산해 `flat_info['layout']` 에 둔다
2. 답안 박스 = 굵은 실선 사각형 가운데 **안에 점선 괘선이 있는 것**(지문 [box] 는 괘선이 없다).
   답 ↔ 박스는 판독이 함께 준 `box_2d` 와 가장 많이 겹치는 것, 없으면 차례대로
3. 줄 = 괘선 사이 띠. **띠의 아래쪽 65% 만 본다** — 위쪽에는 윗줄 받침·꼬리가 내려와
   빈 띠가 '쓴 줄'로 잡혀 판독문 줄과의 짝이 한 칸씩 밀렸다. 잉크가 다른 줄의 20%
   아래인 띠도 빈 줄로 본다
4. 판독문 줄 ↔ 잉크 있는 띠를 차례로 짝짓는다. 줄이 더 많으면(줄 사이에 끼워 쓴
   덧말) **가장 짧은 줄을 윗줄에 붙인다** — 끝줄끼리 붙이면 뒤 줄이 모두 밀린다
5. 구절의 가로 자리 = 띄어쓰기로 나눈 낱말 ↔ 잉크의 큰 틈으로 나눈 덩어리. 개수가 안
   맞으면 잉크 누적량에 비례. 채점 구절이 판독문에 그대로 없으면(회원이 고친 뒤 채점)
   `_fuzzy_find` 로 60% 넘게 닮은 구간을 쓴다

- 실측(세션 146 · 8쪽): 박스 수 = 문항 수 8쪽 모두, 첨삭 45개 전부 자리 찾음, 쪽당 0.12초
- **PDF 저장은 인쇄 방식**(사용자 결정). 결과 머리글 'PDF 저장' → `erPrint()` 가 접힌
  모범답안·해설을 펼치고 문서 제목(=파일 이름)을 바꾼 뒤 `window.print()`. 서버에서 PDF 를
  만들지 않는다 — 시험지 위 첨삭 자리는 화면이 손글씨 폭을 재어 계산해 서버에서 재현이 어렵다
  - `@media print`: A4 10mm 여백, 인쇄 머리말(자격증·회차·응시일·이름·총점), 버튼·탭 감춤,
    점수 입력칸은 글자만, `print-color-adjust: exact`(괘선·첨삭 배경이 빠지지 않게)
  - 내 시험지 첨삭은 쪽마다 `break-before: page`, SVG 높이 272mm 로 A4 한 장에 한 쪽
  - '시험지 쪽만 PDF 저장'(안내 줄) = `body.print-sheets` — 카드·요약을 빼고 쪽만. 첫 쪽에
    나눔을 걸면 첫 장이 머리말만 남고 비었다 → 화면이 첫 쪽에 `sv-first` 를 달아 나눔을 뺀다
    (`:first-of-type` 은 div 가 섞여 듣지 않는다)
  - 확인은 Playwright(`channel='chrome'`) `page.pdf()` 로 했다 — 인쇄 창은 자동화로 못 연다.
    146 재현 기준 답안 첨삭 17장, 시험지 첨삭 22장, 시험지만 8장
- 휴대폰에서는 쪽이 340px 남짓이라 손글씨가 작다. 쪽을 누르면 900px 로 넓혀 옆으로 민다
- 사진에서 박스를 못 찾은 문항은 카드에 입력한 답안 첨삭이 그대로 보인다(`.qr.on-page` 만 감춘다)
