# 실기 필답 모범답안 재서술 지침

## 목적

교재 풀이를 그대로 싣지 않고, **내용을 이해한 뒤 우리 표현으로 다시 쓴다.**
저작권 문제를 피하는 것이 첫째 목적이고, 동시에 **채점하기 좋은 형태**로
정리하는 것이 둘째 목적이다.

## 입력 / 출력

- 입력: `_rewrite/<배치명>.json` — 문항 배열. 각 항목에 `pk`, `text`,
  `answer_items`(기존 풀이), `answer_text`, `reference`, `notes` 가 들어 있다.
- 출력: **같은 파일을 덮어쓴다.** `answer_items`, `answer_text` 를 새 서술로 바꾸고
  `rewritten: true` 를 추가한다. 나머지 필드(`pk`, `text` 등)는 건드리지 않는다.
- **5문항 처리할 때마다 Write로 저장한다.** 중단되어도 진행분이 남도록.
- Bash heredoc 금지. 반드시 Write 도구.

## 재서술 원칙

### 반드시 바꾸는 것
- 문장 구조와 어순. 기존 풀이의 서술 방식을 따라가지 않는다.
- 설명 표현. 같은 뜻을 다른 말로 쓴다.
- 항목 배열 방식. 필요하면 묶거나 나눈다.

### 절대 바꾸지 않는 것 (사실 — 저작물이 아니다)
- 법조문의 조항 번호와 수치: `30일`, `100분의 3`, `1/25,000`, `제12조`
- 기준값·등급 체계: `pH 6.0~6.5`, `생태자연도 1등급`, `EW`
- 학술 용어의 정의와 분류 체계, 종명·학명·법령명
- 계산식과 그 결과

### 품질 기준
1. **문제가 요구한 개수를 정확히 맞춘다.** "3가지"면 정확히 3개.
   기존 풀이에 4개가 적혀 있어도 대표적인 3개만 고르고, 나머지는 버린다.
   (기존 데이터에 개수 불일치가 여럿 있다 — 이번에 바로잡는다)
2. **한 항목에 한 개념만.** 채점 포인트가 되므로 섞으면 부분점수가 어그러진다.
3. 형식은 `① 핵심용어 : 설명` 으로 통일한다. 핵심 용어를 앞에 둔다.
4. 설명은 한 문장으로 끝낸다. 길어야 두 문장.
5. 교재 문체(~이다, ~한다)를 쓴다. 존댓말·구어체 금지.
6. 표가 답이면 `answer_text` 에 마크다운 표로 쓰고 `answer_items` 는 빈 배열.
7. **없는 내용을 지어내지 않는다.** 기존 풀이와 reference에 있는 사실만 쓴다.
   다만 이해를 돕는 짧은 부연(용어의 영문 풀네임 등)은 추가해도 좋다.

## 유형별 처리

| qtype | 방식 |
|---|---|
| 열거 | 항목마다 `① 용어 : 한 줄 설명`. 문제가 요구한 개수만 |
| 서술 | 개념 정의를 ①로, 이어지는 논점을 ②③으로 나눈다. 한 덩어리로 쓰지 않는다 |
| 표그림 | 표는 `answer_text` 에 마크다운 표. 그림이 답이면 무엇을 그려야 하는지 문장으로 서술 |
| 단답 | 정답 용어 + 짧은 정의. `① 매트이식 : …` 형태 |

## 주의

- `notes` 에 원문 오식이 기록된 문항이 있다. **원문 오류는 답에 반영하지 말고
  바른 내용으로 쓴다.** (예: 문제는 "중요도"를 묻는데 풀이가 "우점도"를 계산한 경우
  → 답은 중요도 공식으로 바로잡는다. notes에 그 사실을 덧붙인다)
- `reference` 는 법조문·지침 원문이다. 사실 확인용으로만 읽고, 답에 통째로 옮기지 않는다.
- 기존 풀이가 비어 있거나 그림뿐인 문항은 `reference` 와 문제문을 근거로 서술한다.
  근거가 없으면 빈 배열로 두고 `notes` 에 "답 없음 — 확인 필요"를 적는다.

## 완료 보고

처리 문항 수, 개수 불일치를 바로잡은 문항 목록, 원문 오류를 정정한 문항 목록,
답을 쓰지 못한 문항 목록.
